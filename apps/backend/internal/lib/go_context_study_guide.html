ctx, without the detour

What it is, why it exists, and how your saved code uses it.

Current repository truth: main.go only prints Hello, World!. The server and worker definitions exist, but main does not start them.

1. The whole idea

A lower function can be waiting after its caller no longer needs the result. A context lets the caller send a stop signal to that lower function.

Owner Starts one operation.
→
ctx Carries a stop signal and deadline.
→
Waiting call Stops when it observes the signal.

context.Context is an interface type. ctx is only the usual variable name.

func doWork(ctx context.Context) error

A context does not contain the work. It does not start a goroutine. It does not kill a function. It gives cooperating code a signal.

2. How your code creates ctx

ctx, cancel := context.WithTimeout(
    context.Background(),
    5*time.Second,
)
defer cancel()
  1. Background() returns an empty root context.
  2. WithTimeout creates a child of that root.
  3. The child stores a deadline: now plus five seconds.
  4. Go starts a timer for that deadline.
  5. Go returns the child as ctx.
  6. Go also returns the cancel function.

If five seconds pass, Go closes ctx.Done(). Then ctx.Err() returns context.DeadlineExceeded.

If the work finishes first, the deferred cancel() stops the timer and releases its resources.

How lower code observes it

select {
case <-ctx.Done():
    return ctx.Err()
case result := <-resultChannel:
    return result
}

You do not usually write this check around a database call. You pass ctx to the database library. The library performs the check.

4. Your Asynq example

The producer stores a timeout setting

    TaskWelcome,
    payload,
    asynq.Timeout(30*time.Second),
)

This does not create a live context. It stores a 30-second setting in the task.

The worker creates the live context later

When Asynq starts the task, it creates a context with task metadata and a deadline. It passes that context to your handler.

internal/lib/job/handlers.go

Your chain stops here

The 30-second deadline does not reach the Resend call. Context cancellation is cooperative. A function cannot observe a context that it never receives.

6. Patterns that your code actually uses

  • Manual dependency injection: constructors receive configuration, logger, or server values.
  • Internal construction: server.New creates the database, Redis client, and job service itself.
  • Global state: handlers.go stores emailClient in a package variable.
  • Constructor functions: examples include server.New, database.New, and NewJobService.
  • Middleware: RequireAuth wraps the next handler.
  • Task routing: Asynq maps TaskWelcome to its handler.
  • Functional options: MaxRetry, Queue, and Timeout configure a task.
  • Lifecycle methods: the server and job service have start and stop methods.

There is no completed composition root. There is no queue producer. There is no repository layer. Those are missing parts, not current patterns.

7. Remember these five rules

  1. Create a root only at an operation boundary.
  2. Use WithTimeout when lower work needs a time limit.
  3. Call defer cancel() after you create a cancelable context.
  4. Pass ctx down to every waiting call that accepts it.
  5. Ask where the context chain stops.

The final model: the owner creates or receives a context. Lower functions pass it down. The stop signal works only where code observes it.
